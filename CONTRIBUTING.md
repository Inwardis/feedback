# Contributing feedback

Thanks for helping shape Inwardis! This repository is for **feedback and roadmap** — it holds no
product source code, so there are no pull requests to submit against the app. What we're looking
for here is good issues.

## Before you open an issue

1. **Search** [existing issues](https://github.com/inwardis/feedback/issues?q=is%3Aissue) —
   open and closed. If yours exists, **👍 react** and add detail in a comment instead of opening
   a duplicate. We prioritize by reactions and impact.
2. **Check the [roadmap](ROADMAP.md)** — it may already be planned.
3. **Pick the right template** — [Bug report](https://github.com/inwardis/feedback/issues/new?template=bug_report.yml)
   or [Feature request](https://github.com/inwardis/feedback/issues/new?template=feature_request.yml).
   Questions and open-ended ideas go in [Discussions](https://github.com/inwardis/feedback/discussions).

## What makes a great issue

- **One issue, one thing.** Split unrelated reports.
- **Reproducible.** For bugs: version, steps, and what you expected vs. what happened. The
  "Reference" id from an error toast helps us find it in the logs.
- **Specific.** Screenshots and small examples beat long descriptions.

## What happens next

New issues get a `needs-triage` label. We triage regularly and add area/priority labels; some
move onto the roadmap, some we clarify with questions, and duplicates are linked and closed.
Silence isn't rejection — reactions keep an issue visible.

## Security

**Do not** file security vulnerabilities as public issues. Use
[GitHub's private security advisory form](https://github.com/inwardis/feedback/security/advisories/new)
— see [SECURITY.md](SECURITY.md).

## Code of conduct

Participation is covered by our [Code of Conduct](CODE_OF_CONDUCT.md). Be kind.
